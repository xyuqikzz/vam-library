# vam管理增强插件 1.0.8

1.0.8 移除加载计时面板、F8 快捷键、统计钩子、计时日志及文件定位加速，新增默认开启的 VAR 原生解压。作者排序、文件夹浏览、入库时间与场景启动联动保留。

解压使用游戏自带 Mono 的 zlib，不安装或替换原生库。只替换 `ZipFile.GetInputStream(long)` 中 Deflate 解压器的构造，保留原版文件定位、包头检查、输入边界、归档锁和解密流程。仅处理至少 64 KiB、压缩后体积缩小的非加密 VAR 条目；小文件、无压缩收益条目、非 VAR 与加密资源沿用原版。

启动时进行原生解压自检；与其他插件修改同一方法冲突时停用优化。流式输出校验长度与 CRC，不缓存整份资源；原生读取失败时重新定位压缩输入，用原版解压器重放至已返回的位置，再处理当前读取。原版仍无法读取时保留异常，不将失败视为空资源。原生异常后新的读取沿用原版，其余模组功能继续工作。

纹理解码仍由 VaM 原版处理。检查实际游戏程序集确认 `QueuedImage.ProcessFromStream` 使用 GDI+ Bitmap 解码，并包含翻转、缩放、法线等像素处理；`Finish` 再执行 Unity 纹理上传、mipmap 与压缩。VaM 已有内存和磁盘纹理缓存。本版不替换这套解码/纹理生命周期，不承诺纹理解码、AssetBundle 内部解压、GPU 上传或整场景加速。Unity 的原始纹理数据格式和运行时纹理压缩是不同步骤，见 [LoadRawTextureData](https://docs.unity3d.com/2018.4/Documentation/ScriptReference/Texture2D.LoadRawTextureData.html) 与 [Compress](https://docs.unity3d.com/2018.4/Documentation/ScriptReference/Texture2D.Compress.html)。

567 项测试检查已通过，覆盖输出一致性、分块/单字节读取、并发、提前关闭、读取途中关闭开关、加密/非 VAR 回退、损坏数据、输入失败后恢复、错误长度/CRC、CRC 标准向量及分块边界、其他插件冲突。上表为最终 DLL 首轮完整通过时的基准，复跑会受后台负载影响；游戏内完整场景及长时间运行尚未实测。

需要关闭原生解压时，退出游戏，在 `BepInEx/config/com.vamlibrary.scenebrowser.cfg` 的 `[Performance]` 中将 `NativeDecompression` 改为 `false`，再启动游戏。旧 `FastResourceLookup` 和 `Statistics.ShowOverlay` 配置即使仍留在用户配置文件中，也已不再读取。开发测试脚本会输出基准数据，插件运行时没有时间统计。

1.0.5 将插件统一命名为「vam管理增强插件」，入库时间随软件入库、扫描和资源列表刷新自动同步。设置只保留简短说明、安装状态及安装 / 更新 / 卸载操作，无需单独同步。

1.0.4 新增软件与游戏的场景启动联动。在「包管理 → 资源包详情」中选择包内场景，点击顶部操作区的「启动场景」，即可打开 VaM 并加载该场景；同一区域的「提取角色预设」可展开角色选择与外观预设保存选项。支持桌面模式与 OpenVR 模式；当前实例已运行时直接发送加载请求，沿用当前模式，不重复启动。首次使用需退出游戏并在设置中安装或更新此模组。仅精确哈希匹配的 1.0.0 / 1.0.1 / 1.0.2 / 1.0.3 可以直接更新。

联动通过模组目录下的 `scene-launch` 临时请求与结果文件通信，无网络监听。游戏在初始化及当前加载完成后处理请求，保持 VAR 的精确版本和原场景路径，不解压、修改场景或替换默认场景。请求包含有效期及独立编号，超时或完成后清理，防止下次启动意外重放。软件等待游戏完成加载并确认路径后显示成功；未启用、被禁用、缺失或加载失败会显示错误。按需管理库中的包需先启用映射及依赖。点击启动会切换当前游戏场景，请先保存修改。原生插件安全提示与依赖提示仍由游戏处理；启动或加载超过三分钟时软件报告超时，游戏已开始的加载不会被强制中止。

1.0.3 新增「入库时间」，从新到旧排序。软件从自己的资源索引导出入库时间，游戏场景预览按这个时间排序；同一 VAR 中的场景共用资源包的入库时间。软件支持哈希匹配的 1.0.0 / 1.0.1 / 1.0.2 直接更新。

1.0.2 修复场景预览器没有可见侧栏时文件夹模式显示空白的问题。文件夹、返回上级、返回根目录都作为原生卡片放入场景缩略图网格，参与分页，搜索和收藏筛选不会隐藏导航卡片。软件支持哈希匹配的 1.0.0 / 1.0.1 直接更新。

1.0.1 修复旧版在 VaM CLR 2 中因 `ConditionalWeakTable` 和系统 CLR 4 引用而无法加载的问题。现在使用游戏自带的 mscorlib / System / System.Core 编译。已安装 1.0.0 时，退出游戏并在软件中点击「更新模组」；只更新哈希匹配的已知旧版，不覆盖改动过的 DLL。

这是游戏内 BepInEx 插件，通过 VAM Library 的「设置 → vam管理增强插件」安装。目标为 VaM 1.22.0.13；本次构建使用的游戏、BepInEx 5 和 Harmony 二进制指纹保存在 `src-tauri/resources/mods/scene-browser.json`。安装器校验这些指纹，不会覆盖其他插件或安装 / 升级加载器。

## 使用

1. 退出 VaM，在 VAM Library 设置中选中游戏根目录。
2. 在「vam管理增强插件」中点击「安装插件」或「更新插件」。安装后自动同步入库时间，以后入库或刷新资源时自动更新。
3. 启动游戏，打开「选择要加载的场景」，在原来的排序菜单中选择：
   - **作者 A–Z**：按 VAR 元数据中的作者排序，忽略大小写；同作者按场景名排序。无作者的本地场景放在后面。
   - **按文件夹浏览**：场景缩略图网格中先显示 `[文件夹]` 卡片，再显示当前层 VAR 包里的场景。点击文件夹进入，点击 `.. / 返回上一级` 或 `返回 AddonPackages 根目录` 卡片返回。无需侧边目录栏，根目录没有直接存放 VAR 时仍然显示子文件夹入口。
   - **入库时间**：按软件资源列表使用的首次入库时间降序（新到旧）；时间相同时按作者、场景名和路径保持稳定顺序。没有索引记录的 VAR 场景和本地散装场景放在后面。
4. 选择原有排序方式，或使用原生场景快捷目录，退出文件夹模式。

文件夹模式不递归混合子目录场景，不把 VAR 内部的 `Saves/scene` 当作物理目录。空文件夹和不含场景的文件夹仍可浏览，并保留返回卡片。目录链接与点号开头的内部目录不进入；未被 VaM 索引或禁用的 VAR 不会出现。搜索、隐藏、收藏、分页和点击加载继续由原生浏览器处理，筛选只作用于当前文件夹内的场景，导航卡片始终参与分页。计数包括文件夹卡片。新打开场景选择器时恢复原生排序，不把自定义值写入游戏偏好设置。仅扩展「选择要加载的场景」，不改动外观、保存等其他选择器。

入库时间取自 `packages.scan_time`，与软件中的「入库时间」排序一致；不是文件创建时间或修改时间。重复扫描、移动文件夹和重复索引保留现有入库时间；通过快捷入库实际替换同名同版本资源时，更新为本次成功入库时间，仅保留已安装资源时不更新。已有资源如果此前没有被软件索引，只能从首次扫描开始记录，无法还原更早的真实入库日期。不同包版本分别记录时间。

启动软件、完成扫描 / 入库 / 下载及其他索引变更、刷新资源包 / 场景 / 预设列表、切换游戏实例、清空数据库时会自动更新当前游戏的时间映射。只导出该实例 AddonPackages 与其管理库内的资源，不混入其他游戏目录。映射原子写入 `BepInEx/plugins/VamLibrary.SceneBrowser/import-times.tsv`，内容为版本头和「包 UID、UTC 毫秒时间戳」两列，不包含本地资源路径。游戏开启入库时间排序时每秒检查映射变化；没有变化时保留当前分页。读取失败时保留上次完整数据并提示刷新资源，映射删除或清空后不沿用旧记录。映射不需要软件保持运行，软件关闭后使用最后同步的数据。

安装位置：`BepInEx/plugins/VamLibrary.SceneBrowser/VamLibrary.SceneBrowser.dll`。卸载前退出游戏，再在同一软件入口点击「卸载插件」。卸载保留时间映射文件；重新安装后按当前软件索引更新。安装和卸载不移动任何 VAR，不修改游戏程序集、存档或偏好。安装器仅识别当前版本及指定哈希的旧版 1.0.0 / 1.0.1 / 1.0.2 / 1.0.3 / 1.0.4 / 1.0.5 / 1.0.6 / 1.0.7，其他内容的同名 DLL 会拒绝覆盖和删除。

## 开发和验证

在仓库根目录用 PowerShell 7 执行，`<VaM 根目录>` 为装有兼容 BepInEx 5 的游戏目录：

```powershell
./mods/SceneBrowser/build.ps1 -VamRoot '<VaM 根目录>'
./mods/SceneBrowser/test.ps1 -VamRoot '<VaM 根目录>'
./mods/SceneBrowser/test-runtime.ps1 -VamRoot '<VaM 根目录>'
./mods/SceneBrowser/test-decompression.ps1 -VamRoot '<VaM 根目录>'
npm run build
cargo test --manifest-path src-tauri/Cargo.toml game_mods
cargo test --manifest-path src-tauri/Cargo.toml scene_browser_index
cargo test --manifest-path src-tauri/Cargo.toml scene_launch
$env:VAM_MOD_TEST_ROOT = '<VaM 根目录>'
cargo test --manifest-path src-tauri/Cargo.toml installation_round_trip_with_local_game -- --ignored
npm run tauri -- build --no-bundle
```

构建脚本仅从游戏目录读取程序集，输出本项目的 DLL 和兼容性清单，不部署到游戏。Rust 通过 `include_bytes!` 把模组内置到软件，不依赖运行时源码目录。DLL 与清单需一起保留；重建 DLL 后必须重建软件。游戏程序集和第三方加载器不会打包到软件。重新构建针对其他游戏版本的模组后，还必须核对 API 契约并完成游戏内验收，不能仅以编译成功判断兼容。

规则测试覆盖作者分组、大小写、无作者、同名稳定排序、入库时间降序、无记录后置、映射替换 / 清空 / 错误恢复、根目录、中文嵌套目录、空目录返回、根层无 VAR 的文件夹入口及路径越界。二进制契约检查覆盖 Harmony 钩子及 CLR 2 引用。`test-runtime.ps1` 在独立进程内嵌入游戏自带的 Mono，复现旧版加载失败，并验证修正版类型加载、静态初始化、浏览器状态创建、入库时间读取与排序及全部 9 个 Harmony 补丁挂载 / 卸载，也使用实际 AddonPackages 目录构造原生导航网格条目；不注入运行中的游戏。旧 DLL 仅作为回归测试样本保留，不打包进软件。Rust 测试覆盖软件时间与文件时间的区别、实例边界、管理库、重复副本、迁移后时间保留、完整映射替换与清空、依赖缺失、未知 DLL 保护、卸载保护。显式运行的本机环境测试只读取真实依赖并复制到独立临时目录，验证完整安装、重复安装、旧版升级、哈希和卸载。

仍需游戏内验收：软件启动桌面 / VR 场景、游戏已运行时切换场景、禁用包与缺失依赖提示、桌面与 VR 场景浏览器中的菜单布局、跨页作者分组、入库时间排序及自动刷新、文件夹进入 / 返回、空目录、搜索 / 收藏组合筛选，以及切回全部场景后的点击加载。编译和单元测试不替代这些运行检查。
